# lele_lint rules

Generated by `lele_lint --rules-md`; do not edit by hand. Regenerate with
`just docs` (the `rules_md` test fails while this file is stale).

Every rule is always on and always an error. `lele_lint --explain <CODE>` prints one rule.

Each example is a whole crate. Files not shown get these defaults: an empty `src/lib.rs`,
and a `Cargo.toml`, `clippy.toml` and `lele.toml` that already satisfy the clippy-config rules.
Every **Bad** example reports its rule's code (it may report others too);
every **Good** example reports nothing at all.

## Layout: files and folders

- [LELE001 `atomic_file`](#lele001-atomic_file): One public (`pub` or `pub(crate)`) item per file, and the file is named after it (`guest.rs` holds `pub struct Guest`).
- [LELE002 `snake_case_files`](#lele002-snake_case_files): File and folder names are snake_case.
- [LELE003 `method_file_co_location`](#lele003-method_file_co_location): A `<type>_<method>.rs` file must sit in the same folder as `<type>.rs`.
- [LELE019 `constants_placement`](#lele019-constants_placement): A constant lives in the nearest `constants.rs` (or `__basic__/constants.rs`) shared by all its users.
- [LELE020 `container_placement`](#lele020-container_placement): Behavior-free types (plain structs, enums, newtypes, aliases, ECS markers) go in the domain's `__basic__/<role>.rs`.
- [LELE023 `mod_rs_purity`](#lele023-mod_rs_purity): `mod.rs` holds only `mod`/`pub mod` declarations and `pub use` re-exports.
- [LELE038 `dunder_module_name`](#lele038-dunder_module_name): A dunder folder or file (`__basic__/`) is declared `#[path = "__basic__/mod.rs"] pub mod basic;` and named `basic` everywhere in code.

### LELE001 `atomic_file`

One public (`pub` or `pub(crate)`) item per file, and the file is named after it (`guest.rs` holds `pub struct Guest`).

**Why:** A file name tells you exactly what is inside; finding code means finding a file, and every unit gets its own test.

**Bad** (reports LELE001):

`src/greeting.rs`

```rust
pub fn greet(name: &str) -> String {
    format!("Hello, {name}!")
}

pub fn farewell(name: &str) -> String {
    format!("Bye, {name}!")
}
```

`src/lib.rs`

```rust
mod greeting;
pub use greeting::{farewell, greet};
```

**Good:**

`src/guest.rs`

```rust
use derive_more::Deref;

#[derive(Deref)]
pub struct Guest(pub String);

#[rustfmt::skip]
impl Guest {
    pub fn greet(&self) -> String { format!("Hello, {}!", **self) }
}

#[cfg(test)]
mod tests {
    use super::Guest;

    #[test]
    fn test_usage() {
        assert_eq!(Guest("Ada".to_string()).greet(), "Hello, Ada!");
    }
}
```

`src/host.rs`

```rust
use derive_more::Deref;

#[derive(Deref)]
pub struct Host(pub String);

#[rustfmt::skip]
impl Host {
    pub fn farewell(&self) -> String { format!("Bye, {}!", **self) }
}

#[cfg(test)]
mod tests {
    use super::Host;

    #[test]
    fn test_usage() {
        assert_eq!(Host("Ada".to_string()).farewell(), "Bye, Ada!");
    }
}
```

`src/lib.rs`

```rust
mod guest;
mod host;
pub use guest::Guest;
pub use host::Host;
```

### LELE002 `snake_case_files`

### LELE003 `method_file_co_location`

A `<type>_<method>.rs` file must sit in the same folder as `<type>.rs`.

**Why:** A method file that drifts away from its type is impossible to find from the type.

**Bad** (reports LELE003):

`src/lib.rs`

```rust
pub mod game;
pub mod player;
```

`src/game/mod.rs`

```rust
mod player_rename;

pub use player_rename::rename;
```

`src/game/player_rename.rs`

```rust
use crate::player;

pub fn rename(player: &mut player::Player, name: String) {
    player.name = name;
}
```

`src/player/mod.rs`

```rust
mod player;

pub use player::Player;
```

`src/player/player.rs`

```rust
pub struct Player {
    pub name: String,
    pub health: u32,
}

impl Default for Player {
    fn default() -> Self {
        Self {
            name: String::new(),
            health: 100,
        }
    }
}
```

**Good:**

`methods/mod.rs`

```rust
pub mod player;
```

`src/lib.rs`

```rust
pub mod player;

#[path = "../methods/mod.rs"]
pub mod methods;
```

`methods/player/heal.rs`

```rust
use crate::player;

pub fn heal(player: &mut player::Player, amount: u32) {
    let healed = player.health.saturating_add(amount);
    player.health = healed.min(100);
}

#[cfg(test)]
mod tests {
    use super::heal;
    use crate::player::Player;

    #[test]
    fn test_usage() {
        let mut player = Player {
            name: String::new(),
            health: 10,
        };
        heal(&mut player, 5);
        assert_eq!(player.health, 15);
    }
}
```

`methods/player/mod.rs`

```rust
mod heal;
pub use heal::heal;
```

`src/player/mod.rs`

```rust
mod player;

pub use player::Player;
```

`src/player/player.rs`

```rust
use atomic_delegate_macros::atomic_delegates;

pub struct Player {
    pub name: String,
    pub health: u32,
}

impl Default for Player {
    fn default() -> Self {
        Self {
            name: String::new(),
            health: 100,
        }
    }
}

#[atomic_delegates]
impl Player {
    pub fn heal(&mut self, amount: u32) {}
}

#[cfg(test)]
mod tests {
    use crate::player;

    #[test]
    fn test_usage() {
        let mut player = player::Player::default();
        player.heal(5);
        assert_eq!(player.health, 100);
    }
}
```

### LELE019 `constants_placement`

A constant lives in the nearest `constants.rs` (or `__basic__/constants.rs`) shared by all its users.

**Why:** Constants placed too high leak across domains; placed too low they get duplicated.

**Bad** (reports LELE019):

`src/constants.rs`

```rust
pub const MAX_HEALTH: u32 = 100;
```

`src/lib.rs`

```rust
pub mod constants;
pub mod player;
```

`src/player/health.rs`

```rust
use derive_more::Deref;

use crate::constants;

#[derive(Deref)]
pub struct Health(pub u32);

#[rustfmt::skip]
impl Health {
    pub fn clamped(&self) -> u32 { (**self).min(constants::MAX_HEALTH) }
}

#[cfg(test)]
mod tests {
    use super::Health;

    #[test]
    fn test_usage() {
        assert_eq!(Health(150).clamped(), 100);
    }
}
```

`src/player/mod.rs`

```rust
mod health;

pub use health::Health;
```

**Good:**

`src/lib.rs`

```rust
pub mod player;
```

`src/player/health.rs`

```rust
use derive_more::Deref;

use crate::player;

#[derive(Deref)]
pub struct Health(pub u32);

#[rustfmt::skip]
impl Health {
    pub fn clamped(&self) -> u32 { (**self).min(player::MAX_HEALTH) }

    use super::Health;

```

`src/player/mod.rs`

```rust

pub mod basic;

pub use basic::constants::MAX_HEALTH;
```

`src/player/__basic__/constants.rs`

```rust

```

`src/player/__basic__/mod.rs`

```rust
pub mod constants;
```

### LELE020 `container_placement`

Behavior-free types (plain structs, enums, newtypes, aliases, ECS markers) go in the domain's `__basic__/<role>.rs`.

**Why:** Small data types don't need a file and a test each; grouping them keeps atomic files for code that does something.

**Bad** (reports LELE020):

`src/lib.rs`

```rust
pub mod stock;
```

`src/stock/item.rs`

```rust
pub struct Item {
    pub name: String,
    pub price: u32,
}
```

`src/stock/mod.rs`

```rust
mod item;

pub use item::Item;
```

**Good:**

`src/lib.rs`

```rust
pub mod stock;
```

`src/stock/mod.rs`

```rust
#[path = "__basic__/mod.rs"]
pub mod basic;

pub use basic::structs::Item;
```

`src/stock/__basic__/mod.rs`

```rust
pub mod structs;
```

`src/stock/__basic__/structs.rs`

```rust
pub struct Item {
    pub name: String,
    pub price: u32,
}
```

## Delegates: methods and `methods/`

- [LELE004 `method_visibility`](#lele004-method_visibility): A method file is a private module: declared with `mod`, never `pub mod` or `pub use`.
- [LELE008 `helpers_are_methods`](#lele008-helpers_are_methods): No private `fn` in `src/`: a helper is a `pub(crate)` method or associated fn of the type it serves, never a private free fn or a private method. `fn main` in `main.rs` and test code are exempt.
- [LELE017 `atomic_delegates`](#lele017-atomic_delegates): Hand-written methods have at most 3 statements, and an impl block with one-line methods carries `#[rustfmt::skip]`.
- [LELE018 `constructor_no_skip`](#lele018-constructor_no_skip): `impl Default` and real constructors are never `#[rustfmt::skip]`.
- [LELE021 `no_inner_fns`](#lele021-no_inner_fns): No `fn` inside a function body, except a tree walk's inner `fn recursion`.
- [LELE027 `impl_item_order`](#lele027-impl_item_order): A type's impls in `src/` follow one order: `impl Default`, constructors (receiver-less fns returning `Self`, `impl From`/`TryFrom`/`FromStr`), other trait impls, `pub` fns, then `pub(crate)` fns.
- [LELE030 `methods_layout`](#lele030-methods_layout): Every `#[atomic_delegates]` shell has a body at `methods/<type>/<method>.rs` with `pub fn <method>`, 2+ statements and its own `test_usage` (or a final `// no test_usage necessary`).
- [LELE032 `delegate_macro`](#lele032-delegate_macro): Method shells (empty bodies) are declared in one `#[atomic_delegates]` impl block per type, plus at most one more holding only `pub(crate)` shells; `new` is never delegated.
- [LELE034 `no_free_functions`](#lele034-no_free_functions): A `pub`/`pub(crate)` top-level `fn` in `src/` must be a method of a type: its owner is the first argument's type or the return type; body in `methods/<type>/<method>.rs`. `bevy_systems/`, `__basic__/`, `main.rs`, `build.rs` and `[[lele.lint.entry_points]]` are exempt.
- [LELE035 `methods_are_delegates`](#lele035-methods_are_delegates): A `methods/<type>/<method>.rs` file holds only `use` lines, private `const`s, its delegate body `pub fn <method>` and `#[cfg(test)] mod tests` — no helper fns, types or impls.

### LELE008 `helpers_are_methods`

No private `fn` in `src/`: a helper is a `pub(crate)` method or associated fn of the type it serves, never a private free fn or a private method. `fn main` in `main.rs` and test code are exempt.

**Why:** `src/` lists types and what each can do; `pub` vs `pub(crate)` on the type's own methods tells API from internal machinery, so no helper hides outside the type.

**Bad** (reports LELE008):

`src/lib.rs`

```rust
mod round;
pub use round::Round;
```

`src/round.rs`

```rust
pub struct Round {
    pub hits: u32,
    pub misses: u32,
}

#[rustfmt::skip]
impl Round {
    pub fn score(&self) -> u32 { base(self.hits).saturating_sub(self.misses) }
}

fn base(hits: u32) -> u32 {
    hits.saturating_mul(10)
}

#[cfg(test)]
mod tests {
    use super::Round;

    #[test]
    fn test_usage() {
        assert_eq!(Round { hits: 1, misses: 0 }.score(), 10);
    }
}
```

**Good:**

`src/lib.rs`

```rust
mod round;
pub use round::Round;
```

`src/round.rs`

```rust
pub struct Round {
    pub hits: u32,
    pub misses: u32,
}

#[rustfmt::skip]
impl Round {
    pub fn score(&self) -> u32 { Self::base(self.hits).saturating_sub(self.misses) }
    pub(crate) fn base(hits: u32) -> u32 { hits.saturating_mul(10) }
}

#[cfg(test)]
mod tests {
    use super::Round;

    #[test]
    fn test_usage() {
        assert_eq!(Round { hits: 1, misses: 0 }.score(), 10);
    }
}
```

### LELE021 `no_inner_fns`

No `fn` inside a function body, except a tree walk's inner `fn recursion`.

**Why:** A nested helper hides from the type that owns it; only the recursion's own walk belongs inside its public function (RATIONALE §11).

**Bad** (reports LELE021):

`src/lib.rs`

```rust
mod round;
pub use round::Round;
```

`src/round.rs`

```rust
pub struct Round {
    pub hits: u32,
    pub misses: u32,
}

impl Round {
    pub fn score(&self) -> u32 {
        fn base(hits: u32) -> u32 {
            hits.saturating_mul(10)
        }
        base(self.hits).saturating_sub(self.misses)
    }
}

#[cfg(test)]
mod tests {
    use super::Round;

    #[test]
    fn test_usage() {
        assert_eq!(Round { hits: 1, misses: 0 }.score(), 10);
    }
}
```

**Good:**

`methods/mod.rs`

```rust
pub mod tree;
```

`src/lib.rs`

```rust
pub mod tree;

#[path = "../methods/mod.rs"]
pub mod methods;
```

`methods/tree/mod.rs`

```rust
mod total;
pub use total::total;
```

`methods/tree/total.rs`

```rust
use crate::tree;

pub fn total(tree: &tree::Tree) -> u32 {
    fn recursion(tree: &tree::Tree, out: &mut u32) {
        *out = out.saturating_add(tree.value);
        for child in &tree.children {
            recursion(child, out);
        }
    }

    let mut out = 0;
    recursion(tree, &mut out);
    out
}

#[cfg(test)]
mod tests {
    use super::total;
    use crate::tree::Tree;

    #[test]
    fn test_usage() {
        let leaf = Tree {
            value: 2,
            children: Vec::new(),
        };
        let root = Tree {
            value: 1,
            children: vec![leaf],
        };
        assert_eq!(total(&root), 3);
    }
}
```

`src/tree/mod.rs`

```rust
mod tree;

pub use tree::Tree;
```

`src/tree/tree.rs`

```rust
use atomic_delegate_macros::atomic_delegates;

#[derive(Default)]
pub struct Tree {
    pub value: u32,
    pub children: Vec<Tree>,
}

#[atomic_delegates]
impl Tree {
    pub fn total(&self) -> u32 {}
}

#[cfg(test)]
mod tests {
    use crate::tree;
```

### LELE039 `no_stringified_errors`

```rust
            path: path.to_path_buf(),
            message: error.to_string(),

        Ok(Self(text))
    }
}

mod tests {

    use super::ConfigText;
```

```rust

```

`src/error.rs`

### LELE028 `clippy_config_cargo`

`Cargo.toml` has `[lints.clippy]` with `pedantic`/`nursery` denied at priority -1 and the 13 required deny lints (or inherits them from the workspace).

**Why:** Every crate gets the same strict baseline, so no crate silently allows unwraps, panics or lossy casts.

**Bad** (reports LELE028):

`Cargo.toml`

```toml
[package]
name = "example"
version = "0.1.0"
edition = "2021"
```

**Good:**

`Cargo.toml`

```toml
[package]
name = "example"
version = "0.1.0"
edition = "2021"

[lints.clippy]
pedantic = { level = "deny", priority = -1 }
nursery = { level = "deny", priority = -1 }
unwrap_used = "deny"
expect_used = "deny"
indexing_slicing = "deny"
arithmetic_side_effects = "deny"
unreachable = "deny"
unimplemented = "deny"
unchecked_time_subtraction = "deny"
todo = "deny"
string_slice = "deny"
panic_in_result_fn = "deny"
panic = "deny"
exit = "deny"
as_conversions = "deny"
```
