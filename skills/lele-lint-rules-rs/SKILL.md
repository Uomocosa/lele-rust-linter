# lele-lint rules

Generated by `lele-lint --skill-md`; do not edit by hand. Regenerate with `just docs`.

This is the rule index: what each rule wants and how to fix it. For the design ideas behind
the rules (domains, atomic files, delegates), load the `lele-syntax-rs` skill. Bevy rules
(`LELEBEVY0xx`) are covered by the `bevy-ui-preview` skill.

## How to clear lint errors

1. Run the linter: `just lint`, or `lele-lint --config lele.toml <crate>`. Each error shows
   its file and line, a `help:` line with the fix for that exact site, and the run ends with
   the error count per rule.
2. Fix ONE rule code at a time, in the order of the sections below (layout first, style
   last). Between codes in the same section, start with the one that has the fewest errors.
   `lele-lint --only <CODE> <crate>` shows just that code's errors (comma-separate several).
3. Unsure what a rule wants? `lele-lint --explain <CODE>` prints a Bad and a Good example
   crate. Copy the Good shape.
4. Re-run the linter after each code: fixes cascade, so the list changes every time.
5. Never silence or loosen a rule: no `#[allow]`/`#[expect]`, no new exemptions or allow
   entries in `lele.toml`, `Cargo.toml` or `clippy.toml` (adding the required clippy
   baseline for LELE028/LELE029 is fine). If a fix seems to need one, stop and ask the user.

## Every file you create or edit

A fix for one rule must not break another. Before saving, check the file against this list
(most cascades come from new files):

- Named in snake_case after its one public item (LELE001, LELE002).
- Ends with `#[cfg(test)] mod tests` holding a `test_usage` test, or with
  `// no test_usage necessary` when there is nothing to test (LELE009).
- No comments (LELE031): before deleting one, move what it says into the item's name or its
  `test_usage` test. No `#[allow]`/`#[expect]` (LELE024).
- Imports the domain, not the item (`use crate::stock;` then `stock::Item`, LELE016);
  no `super::` outside tests (LELE013); `crate::` only in `use` lines (LELE025).
- Helpers are `pub(crate)` methods of a type, never private or free fns (LELE008, LELE034).
- A data type with no `impl` goes in the domain's `__basic__/` (LELE020).
- A method body over 3 statements lives in `methods/<type>/<method>.rs` (LELE017, LELE030).

## Layout: files and folders

- **LELE001 `atomic_file`**: One public (`pub` or `pub(crate)`) item per file, and the file is named after it (`guest.rs` holds `pub struct Guest`).
  - Fix: Give each extra public item its own file named after it (`pub struct Guest` → `guest.rs`), or rename the file to match its single item; then update the `mod`/`pub use` lines.
- **LELE002 `snake_case_files`**: File and folder names are snake_case.
  - Fix: Rename the file or folder to snake_case and update the `mod` line that declares it.
- **LELE003 `method_file_co_location`**: A `<type>_<method>.rs` file must sit in the same folder as `<type>.rs`.
  - Fix: Move `<type>_<method>.rs` into the folder that holds `<type>.rs`; if it is not a method of that type, rename it after its own item.
- **LELE019 `constants_placement`**: A constant lives in the nearest `constants.rs` (or `__basic__/constants.rs`) shared by all its users.
  - Fix: Move the constant into `constants.rs` (or `__basic__/constants.rs`) of the nearest folder that contains every file using it, creating the file if needed, and import it from there.
- **LELE020 `container_placement`**: Behavior-free types (plain structs, enums, newtypes, aliases, ECS markers) go in the domain's `__basic__/<role>.rs`.
  - Fix: Move the behavior-free type into its domain's `__basic__/<role>.rs` (`structs.rs`, `enums.rs`, ...) and import it as `basic::<Type>`; a type with an `impl` keeps its own file.
- **LELE023 `mod_rs_purity`**: `mod.rs` holds only `mod`/`pub mod` declarations and `pub use` re-exports.
  - Fix: Move every item that is not `mod`, `pub mod` or `pub use` out of `mod.rs` into its own atomic file, and re-export it from `mod.rs`.
- **LELE038 `dunder_module_name`**: A dunder folder or file (`__basic__/`) is declared `#[path = "__basic__/mod.rs"] pub mod basic;` and named `basic` everywhere in code.
  - Fix: Declare the folder as `#[path = "__basic__/mod.rs"] pub mod basic;` and write `basic::` in every path, never `__basic__`.

## Delegates: methods and `methods/`

- **LELE004 `method_visibility`**: A method file is a private module: declared with `mod`, never `pub mod` or `pub use`.
  - Fix: Change `pub mod <method_file>;` to `mod <method_file>;` and remove any `pub use` of it; callers use the type's method instead.
- **LELE008 `helpers_are_methods`**: No private `fn` in `src/`: a helper is a `pub(crate)` method or associated fn of the type it serves, never a private free fn or a private method. `fn main` in `main.rs` or a `src/bin/*.rs` binary and test code are exempt.
  - Fix: Turn the private `fn` into a `pub(crate)` method or associated fn of the type it serves: an inline one-liner, or an `#[atomic_delegates]` shell with its body in `methods/<type>/<fn>.rs`.
- **LELE017 `atomic_delegates`**: Hand-written methods have at most 3 statements, and an impl block with one-line methods carries `#[rustfmt::skip]`.
  - Fix: Move each method longer than 3 statements to `methods/<type>/<method>.rs` behind an empty shell in the type's `#[atomic_delegates]` block; put `#[rustfmt::skip]` on blocks of one-line methods.
- **LELE018 `constructor_no_skip`**: `impl Default` and real constructors are never `#[rustfmt::skip]`.
  - Fix: Move `impl Default` and real constructors out of the `#[rustfmt::skip]` block into an impl block without the attribute.
- **LELE021 `no_inner_fns`**: No `fn` inside a function body, except a tree walk's inner `fn recursion`.
  - Fix: Lift the inner `fn` out of the body into a `pub(crate)` method or associated fn of the type that owns the outer function; only a tree walk's `fn recursion` may stay inside.
- **LELE027 `impl_item_order`**: A type's impls in `src/` follow one order: `impl Default`, constructors (receiver-less fns returning `Self`, `impl From`/`TryFrom`/`FromStr`), other trait impls, `pub` fns, then `pub(crate)` fns.
  - Fix: Reorder the type's impl blocks and items: `impl Default`, constructors and `From`/`TryFrom`/`FromStr`, other trait impls, `pub` fns, then `pub(crate)` fns.
- **LELE030 `methods_layout`**: Every `#[atomic_delegates]` shell has a body at `methods/<type>/<method>.rs` with `pub fn <method>`, 2+ statements and its own `test_usage` (or a final `// no test_usage necessary`).
  - Fix: Create `methods/<type>/<method>.rs` with `pub fn <method>` (the receiver becomes the first argument), at least 2 statements and a `test_usage` test, then run `lele-lint --sync-methods <crate>` to update the `methods/` `mod.rs` indexes.
- **LELE032 `delegate_macro`**: Method shells (empty bodies) are declared in one `#[atomic_delegates]` impl block per type, plus at most one more holding only `pub(crate)` shells; `new` is never delegated.
  - Fix: Gather every empty-bodied shell of the type into one `#[atomic_delegates] impl <Type>` block (plus at most one block holding only `pub(crate)` shells), keep hand-written methods in a plain block, and never delegate `new`.
- **LELE034 `no_free_functions`**: A `pub`/`pub(crate)` top-level `fn` in `src/` must be a method of a type: its owner is the first argument's type or the return type; body in `methods/<type>/<method>.rs`. `bevy_systems/`, `__basic__/`, `main.rs`, `build.rs` and `[[lele.lint.entry_points]]` are exempt.
  - Fix: Make the fn a method of its owner (the first argument's type, else the return type; wrap the argument in a newtype if neither is a crate type): add an empty shell to the owner's `#[atomic_delegates]` block, put the body in `methods/<owner>/<fn>.rs`, and run `lele-lint --sync-methods <crate>`. A real process entry point needs a `[[lele.lint.entry_points]]` entry, which is the user's call.
- **LELE035 `methods_are_delegates`**: A `methods/<type>/<method>.rs` file holds only `use` lines, private `const`s, its delegate body `pub fn <method>` and `#[cfg(test)] mod tests` — no helper fns, types or impls.
  - Fix: Move every helper fn, type or impl out of the method file into `src/` as a `pub(crate)` method or type of the type it serves; leave only `use` lines, private `const`s, `pub fn <method>` and its tests.

## Imports and re-exports

- **LELE005 `no_cross_domain_reexport`**: A `mod.rs` re-exports only items from its own folder; cross-domain re-exports go in `lib.rs`.
  - Fix: Delete the `pub use` of another domain's item from this `mod.rs` and add it to `lib.rs` instead.
- **LELE011 `no_stuttered_path`**: No `meters::Meters` paths for crate-root modules: import the type once and write `Meters`.
  - Fix: Import the type once (`use crate::Meters;`) and write `Meters` instead of `meters::Meters`.
- **LELE013 `no_super_imports`**: `super::` is allowed only inside `#[cfg(test)]`; production code imports the domain (`use crate::stock;`).
  - Fix: Replace `super::x` with the domain path: add `use crate::<domain>;` and write `<domain>::x`.
- **LELE015 `root_reexport`**: A public type in a crate-root file is re-exported from `lib.rs` (`pub use meters::Meters;`); a root fn file is a private `mod` plus `pub use`.
  - Fix: In `lib.rs`, declare the root file as a private `mod meters;` and re-export its item with `pub use meters::Meters;`.
- **LELE016 `domain_import`**: Import the domain, not the item: `use crate::stock;` then `stock::Item`.
  - Fix: Import the domain, not the item: `use crate::stock;` at the top, then write `stock::Item` at each use site.
- **LELE025 `no_crate_paths`**: `crate::` appears only in `use` items (outside `lib.rs`/`main.rs`).
  - Fix: Move each `crate::a::B` used in the body into a `use` line at the top of the file and use the short name.
- **LELE033 `boundary_imports`**: A `[[lele.boundary]]` folder may not use any path from its `cannot_use` list.
  - Fix: Remove the forbidden import from the boundary folder and pass the needed data in from outside; never edit `lele.toml` to allow it.

## Types

- **LELE010 `no_positional`**: No positional field access (`.0`, `.1`).
  - Fix: Replace `.0` with deref (`*value`) on single-field newtypes; give tuple structs with two or more fields named fields.
- **LELE012 `no_stuttered_type`**: A type does not repeat its folder's name (`freenet::Client`, not `freenet::FreenetClient`).
  - Fix: Drop the folder name from the type name (`freenet::FreenetClient` → `freenet::Client`) and update every use.
- **LELE014 `no_trivial_accessors`**: No getters or setters that only read or write a public field, including through `Ok(..)`/`Some(..)` or a plain conversion (`.clone()`, `.as_str()`, ...).
  - Fix: Delete the getter or setter and make callers read or write the public field directly.
- **LELE022 `single_field_newtype`**: A struct with one field is a tuple newtype deriving `Deref`; two or more fields are named.
  - Fix: Rewrite a one-field struct as `pub struct X(pub T)` with `#[derive(Deref)]` (`derive_more`) and read it as `*x`; give structs with two or more fields named fields.
- **LELE026 `no_collection_newtype`**: No newtype around a collection (`Rooms(Vec<String>)`); wrap the element (`Room(String)`) and use `Vec<Room>`.
  - Fix: Delete the collection wrapper; wrap the element instead (`Room(String)`) and hold a plain `Vec<Room>`.
- **LELE036 `conversion_is_from`**: An associated fn that builds `Self` (or `Result<Self, _>`) from exactly one argument is a conversion: write it as `impl From<A> for Self` (`TryFrom<A>` when fallible). `new`, `Option<Self>`, trait impls and fns taking a `Self` argument (merges) are exempt.
  - Fix: Replace the one-argument builder with `impl From<A> for <Type>` (`impl TryFrom<A>` if it returns `Result`) and update callers to `Type::from(a)` or `a.into()`.
- **LELE037 `constructor_naming`**: An associated fn with two or more arguments and no `self` that returns `Self` is named `from_*`; one returning `Result<Self, _>` or `Option<Self>` is named `try_from_*`. `new`, trait impls and fns taking a `Self` argument (merges) are exempt.
  - Fix: Rename the constructor to `from_<what>` when it returns `Self`, or `try_from_<what>` when it returns `Result<Self, _>` or `Option<Self>`.
- **LELE039 `no_stringified_errors`**: A caught error is never stored as text in the crate's own error enum (`map_err`, `impl From`, or a helper taking `…Error`): keep it as a `#[source]`/`#[from]` field.
  - Fix: Keep the caught error as a typed field: `#[from] source: io::Error` or `#[source]`, instead of `.to_string()` or `format!`.
- **LELE040 `error_message_omits_source`**: An `#[error("…")]` message does not print its own source (the `#[from]`/`#[source]`/`source` field); use `#[error(transparent)]` to forward it instead.
  - Fix: Remove the source field (`{0}`, `{source}`) from the `#[error("…")]` text, or use `#[error(transparent)]` to forward it.

## Tests

- **LELE006 `no_dunder_tests`**: No `#[cfg(test)]` inside `__basic__/` containers.
  - Fix: Delete the `#[cfg(test)]` block from the `__basic__/` file and test the method or function that uses the type instead.
- **LELE007 `test_inline`**: Unit tests live in the same file as the code (no `tests/` folders under `src/`).
  - Fix: Move the test into a `#[cfg(test)] mod tests` at the bottom of the file it tests and delete the `tests/` folder under `src/`.
- **LELE009 `test_usage`**: Every non-trivial file has a `#[cfg(test)] mod tests` with a `test_usage` test, or ends with `// no test_usage necessary`.
  - Fix: Add `#[cfg(test)] mod tests { #[test] fn test_usage() { .. } }` that calls the file's item and asserts its result; only a file with nothing to test ends with `// no test_usage necessary`.

## Style

- **LELE024 `no_allow_attributes`**: No `#[allow(...)]`/`#[expect(...)]` unless whitelisted in `lele.toml` with the exact lint, file and a reason.
  - Fix: Remove the `#[allow]`/`#[expect]` and fix the code the lint points at; a whitelist entry in `lele.toml` is the user's decision, never yours.
- **LELE031 `no_comments`**: No comments in `src/` or `methods/`, except a final `// no test_usage necessary`.
  - Fix: Delete the comment and move its meaning into names, types or the `test_usage` test.

## Crate config

- **LELE028 `clippy_config_cargo`**: `Cargo.toml` has `[lints.clippy]` with `pedantic`/`nursery` denied at priority -1 and the 13 required deny lints (or inherits them from the workspace).
  - Fix: Add the `[lints.clippy]` block shown by `lele-lint --explain LELE028` to `Cargo.toml`, or `[lints] workspace = true` in a workspace that defines it.
- **LELE029 `clippy_config_clippy`**: `clippy.toml` sets `allow-unwrap-in-tests`, `allow-expect-in-tests`, `allow-panic-in-tests` and `allow-indexing-slicing-in-tests` to `true`.
  - Fix: Add `allow-unwrap-in-tests`, `allow-expect-in-tests`, `allow-panic-in-tests` and `allow-indexing-slicing-in-tests` set to `true` in `clippy.toml`.
